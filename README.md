# Stay on Task · 把任务做在点上

一个面向长任务的 Codex Skill。它让助手自己查清能查的事，先给你判断，并在工作偏离首要目标时主动调整。

比如你让助手“优先加快导入，顺带把安装包做小”。同一批数据原来要 60 秒，新版要 72 秒。即使安装包小了 30%，助手也应该先告诉你新版每次多花 12 秒，然后去查时间慢在哪一步。

## 什么时候用

- **任务卡在内部细节。** 两份输出都像最终稿时，助手从运行记录或文件内容核对归属。
- **长时间看不到结果。** 开始一轮耗时工作前，先确定什么时候能看到第一份可比较的结果。到了那个时间还没结果，就检查进度，必要时缩小试验或换方向。
- **技术诊断需要说清楚。** 先回答能不能用、慢在哪里，或原因是否已经查明，再给足以支持判断的证据。
- **原创方案看起来眼熟。** 把构思放进另一道题里试一试。如果换个名字和布景就能照搬，就让原题独有的条件改变实际玩法或故事。

## 安装

在 Codex 对话中发送下面这句话。

```text
$skill-installer 请从 https://github.com/sdcsky33-beep/stay-on-task/tree/main/skills/stay-on-task 安装 stay-on-task。
```

## 把三条规则设为全局默认

装好后，Codex 可以在任务匹配时自动选用这个 Skill。安装本身不会改动你的个人全局指令。如果希望这台电脑上的每个新任务都遵守下面三条，把这段提示词复制给 Codex 一次即可。设置后，即使某次任务没有选用 Skill，这三条仍是你的默认要求。

```text
请把下面三条写进我的 Codex 个人全局指令，适用于今后所有项目的新任务。保留已有内容，已有同义规则就沿用。

1. 该查的自己查清楚。先用现有材料和已获授权的操作核实影响结果的事实。只有确实需要我的信息、偏好或授权时，再问我。
2. 跟我说时先给判断。先回答我最关心的问题，再给必要依据。原因还没查明就直说，并区分已经确认的事实和待验证的猜测。
3. 发现方向跑偏就主动调整。按我最新的首要目标衡量进展。有证据表明当前做法偏离目标时，在已有授权内直接调整并继续推进，不用等我提醒。

请实际保存这些指令，完成后告诉我它们写到了哪个文件。
```

## 使用

要在某个任务里明确使用完整的 Skill，可以在请求开头写技能名。

```text
$stay-on-task 帮我查清这次导入为什么变慢。优先缩短用户等待时间，安装包大小放在第二位。
```

完整规则见 [SKILL.md](skills/stay-on-task/SKILL.md)。
